## Admission

An AIUser product session remains `authType: aiuser`. The billing server resolves its signed, active product-session principal to a previously and explicitly linked, active phone account. It uses that existing phone UUID only inside the server to quote, reserve, settle and refund the existing ledger. The browser cannot choose the debit account. Association alone does not enable billing, and billing never creates a link, a phone account or a credit grant.

The earlier association itself still requires the same browser to carry an active verified phone session and an AIUser product session whose `idpAuthenticatedAt` came from the signed ID token `auth_time` within the five-minute proof window. Ordinary AIUser login may lack that claim. The account page now offers a separate, explicit `POST /api/auth/aiuser/account-link/reauth` after the user has signed in to the existing phone account in the same browser. This route requires both link selectors, current product and recent signed phone proofs, and uncached association DB posture. It accepts exactly `{}` from the fixed AIstory origin and returns an authorization URL with the fixed registration tuple plus `max_age=0`; it accepts no return URL. The encrypted transaction binds `account_link_reauth_v1`, and callback rejects that purpose unless the signed ID token carries `auth_time` no earlier than transaction start minus clock skew and no older than five minutes. Ordinary start leaves `max_age` absent. The callback still returns only to `/auth/aiuser`, rotates the AIUser product session, and does not clear the phone cookie. The user must still explicitly prepare and confirm the one-to-one association. Product-session issuance time is never a recent-auth substitute. Host code inspection found the deployed AIUser OIDC provider supports `max_age=0` and signed `auth_time`; a real account/UI end-to-end test remains necessary before admission.

`AISTORY_AIUSER_LINKED_BILLING_MODE` is an independent exact selector. The only enabled value is `aistory-aiuser-linked-billing-v1:enabled`. Missing or any other value keeps AIUser platform credit spending closed. It does not replace the existing link admission selector, sticky link revocation selector, global `AISTORY_PLATFORM_BILLING_ENABLED=true`, billing database gate or provider/price gates. Phone-session billing and BYOK retain their existing behavior. Hosted BYOK, cloud progress and administrator authority stay phone-only or otherwise independently gated.

Every AIUser billing attempt requires a current verified product session and an uncached independent linked-billing DB posture plus service-role resolver RPC. The SQL resolves only a committed mapping and checks the existing phone user remains active. A missing mapping, bad session, database drift, unexpected RPC shape or inactive account fails closed before a provider call. The public account projection may show a balance and billing capability, but never the phone UUID, provider subject, token or internal principal key. Readiness is visibility only; generation still reserves through the formal billing gate.
